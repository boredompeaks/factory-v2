# 20 — Implement
**Mode:** `BUILD`
**Purpose** Make the smallest change that satisfies the task and its acceptance refs, inside the scope, in the style of the surrounding code.
**Inputs**
- The validated worktree state from `10-worktree.md`.
- The task context and acceptance refs (read-only).
- `policies/task-limits.json`, `policies/layers.json`, `policies/changelog.json`, `policies/gate.json`, `schemas/task.json`.
**Memory** Read `basemind_memory` (`list`/`search` filtered by `role:builder`) at orientation; put one record at task end and whenever a seam, gotcha, or decision is found. Memory is advice, never evidence; re-run a remembered finding before citing it (`sop/00-memory.md`).

**Procedure**
1. Read every acceptance ref before editing. Hash each with `factory evidence hash` at the task context head and keep the hash; `30-tests.md` compares it after the change.
2. Map the code you will touch with `basemind_code` (`grep`, `references`, `callers`) and `basemind_graph` where an edge matters. Record every production caller, not just the reported one.
3. Choose the smallest diff that satisfies the task. No refactor, rename, reformat, dependency bump, or cleanup outside the ticket.
4. Preserve behavior outside the ticket. Do not remove a conditional or guard unless the task requires it; if you do, plan the covering test in `30-tests.md` and declare it in `guard_delta`.
5. Write only with the native `write` and `edit` tools, only under `task context`. The server intercepts every write: a path outside scope, or a secret or policy path, is refused; a test-infrastructure path is writable only when `task context` names it, and builder never seeks that grant for test configuration, shared fixtures, or CI. A rejected path is terminal for the turn: do not retry it wider, rename it, or route around it. Never touch generated files, secrets, or another lane's worktree.
6. Match the file's existing naming, imports, and error handling. Write no verbose comments: no block that narrates the diff or restates the task; a comment earns its place only by recording a non-obvious why. Follow the repository conventions for money, permissions, transactions, and configuration; do not restate them here.
7. Put the task id in the function or block you edit, once, at the narrowest scope (a trailing `# task: <task_id>` or the changed function's docstring). Do not scatter it across the file.
8. Treat exploit/reproducer tests authored by the auditor or hacker as read-only inputs. Builder-owned unit tests are the only tests you write or edit; never edit, rename, move, skip, xfail, or delete an exploit test to make it pass.
9. Add no hardcoded secret, URL, environment value, coverage pragma, or new dependency without an explicit architecture declaration. `task context` carries the grant; `policies/layers.json` is read-only, so record the same declaration — task id, kind, from, to, reason, and a `declaration_ref` of `path#anchor` — in `backend/docs/requests.md` for the owner to fold into the layer map. `backend/docs/requests.md` is non-exempt in `policies/changelog.json`, so it needs its own changelog row. If that path is outside `task context`, return `BLOCKED SCOPE_INSUFFICIENT`; never edit `policies/layers.json` or create a policy file.
10. Add the changelog row defined by `policies/changelog.json` through `write`/`edit`; one row per non-exempt path group.
11. If a needed path is outside scope, stop with `BLOCKED SCOPE_INSUFFICIENT` and `needed_paths`. If the task exceeds a limit, stop with `BLOCKED SPLIT_REQUIRED`; never partially implement and call it done.
12. Hand the changed file set and the pre-change hashes to `30-tests.md`. **Product scope** Migrations (`backend/**/migrations/**`, `**/*.sql`), requirements and dependency pins (`**/requirements*.txt`, `**/pyproject.toml`, lock files), Docker and compose (`**/Dockerfile`, `**/docker-compose*.yml`), settings and env configuration (`backend/**/settings*`, `backend/settings.py`; `.env*` stays secret-denied and is never a builder write), and all product code are product scope. Builder owns those writes: each goes through `write`/`edit` under `task context` like any other product change, with the changelog row of step
10. Being infrastructure-shaped is not a reason to defer the edit, to skip the migration or pin that the change requires, or to treat the path as test infrastructure. The proof is runnable: precheck runs `SUITE` on sqlite and postgres and `BOOTTEST` with production settings and `DEBUG=false`, and audit re-runs them at head plus `factory k1 migrate` / `factory k1 makemigrations check`. A needed path outside scope is still `BLOCKED SCOPE_INSUFFICIENT` with `needed_paths`. **Test infrastructure** `pytest.ini`, `tox.ini`, `setup.cfg`, `conftest.py`, `.coveragerc`, `Makefile`, `scripts/test*`, `.github/workflows/**`, and any fixture module imported by a test you did not author are test infrastructure. Such a path is writable only when `task context` names it; builder never seeks that grant for test configuration, shared fixtures, or CI, and `.github/**` belongs to the release-engineer. New test modules and builder-owned unit test files under the product test tree (`backend/**/tests/**`, `tests/**`) are writable when `task context` names them; that scope grant is also what lets `TEST_INFRA` pass. `policies/gate.json#test_infra_paths` lists the enforced subset. Keep a needed fixture local to the new test module; if a shared-fixture or config change is unavoidable, return `BLOCKED SCOPE_INSUFFICIENT` with `needed_paths` instead of editing it.
**Routing / handoff**
Continue to `30-tests.md`. Return only to the orchestrator; builder has no subagent or peer channel and does not consume another role's report.
**Policy refs**
`policies/task-limits.json`, `policies/layers.json`, `policies/changelog.json`, `policies/checks.json`, `policies/gate.json`, `policies/task-kinds.json`, `schemas/task.json`, `policies/schemas/builder-result.json`, `agents/builder.md`, `skills/builder/SKILL.md`.
**Done / failure codes**
Done: scoped edit set complete and ready for test proof.
Failure: `BLOCKED SCOPE_INSUFFICIENT`, `BLOCKED SPLIT_REQUIRED`, `BLOCKED ARCH_VIOLATION`, or `BLOCKED GUARD_UNCOVERED`; no out-of-scope write is made.
