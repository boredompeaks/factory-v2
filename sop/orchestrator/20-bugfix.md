# 20 — Bugfix
**Mode:** `BUGFIX`
**Purpose** Repair a defect through repro, confirm, patch, quality, blast radius, delta, verdict. Results return to the orchestrator. **Topology** The hacker is dispatched only by the release-engineer at GATE (`sop/release-engineer/15-campaign.md`) and by the auditor in a `BUG_FINDING` sweep (`sop/auditor/30-hacker-relay.md`). A build or repair task dispatches no hacker. No peer messaging.
**Inputs** Defect report (expected/observed, ids, locus); tier and kind from `policies/risk-map.json` and `policies/task-kinds.json`; acceptance/repro refs; `policies/tiers.json`, `policies/checks.json`, `policies/dispatch-rules.json`, `policies/severity.json`, `policies/escalation.json`.
**Memory** Read `basemind_memory` (`list`/`search` filtered by `role:orchestrator`) at orientation; put one record at task end and whenever a seam, gotcha, or decision is found. Memory is advice, never evidence; re-run a remembered finding before citing it (`sop/00-memory.md`).

**Procedure**
1. **Triage.** Classify `FIX` or `SECURITY`; resolve the highest matching tier/scope. Apply `policies/dispatch-rules.json` before builder (compliance precedes builder only for spec/requirements/compliance scopes; a plain security or money fix does not). Mint with `factory task new --title ... --base <commit>` and record the `dispatch_rules` the mint returns: an empty list on a money or security scope means the matcher missed, not that no rule applies (`docs/DISPATCH-RULES.md`). Record task/lineage/defect ids. No observable behavior -> `80-bug-finding.md`, never guess.
2. **Repro (orchestrator -> auditor).** Mint a fresh auditor task context at the task head/tree; dispatch a session with `task_id` and the bug facts. The auditor brings up K1 only when it must execute probes, reproduces the claim with `factory repro`, admits only under the admission rule, tears K1 down, and returns the repro ref, the probe/test ref, `introduced`, severity, finding ids, and verdict. The auditor does not dispatch a hacker here.
3. **Confirm.** Validate schema and envelope. A finding needs `repro_ref` and `introduced`; a hacker `REPRODUCED` claim without a repro is not actionable. If unconfirmed, `HALT` or route to `80`; never send a guess to builder.
4. **Patch.**
- **P2/P3:** reuse the same builder context that produced the audited change by passing `subagent.sessionID` for that builder; mint a repair task context at the current head/tree and re-enter it. Do not open a second builder window. If the harness reports the prior session unavailable, mint a fresh builder task context, pass the prior task context/result refs and the failing probe verbatim, and record the fallback; never start a bare new window without the failing probe. The builder receives the auditor's failing probe/test unchanged, reproduces it red, patches, and runs it until it passes. It may run the returned probe but may never edit, weaken, skip, or xfail it. Then follow `builder/20`-`50`.
- **P1, or a product-code defect that is a new task:** mint a fresh builder task context and open a new builder window. Follow `builder/20`-`50`.
5. **Quality and blast radius — one auditor session, not two.** Mint one delta task context at the patch head/tree with `parent_task_id` set to the pre-patch task context. In that session run the tier's required checks and the blast-radius probes concurrently within the auditor's own envelope. No hacker child runs in BUILD; the one release-train campaign runs at GATE (`sop/release-engineer/15-campaign.md`). Quality and blast radius are one verdict, not two sessions. Never reuse the pre-patch repro verdict.
6. **Delta — the same task context and session.** The same auditor runs `15-delta.md` on the repair: old exploit dead, 2-3 variants fail closed, patch compared, silent regressions checked. For P2/P3 the session continues; a P1 repair keeps the session but had a new builder window. If the tier rises, mint a fresh task context and session before continuing. The delta report states whether the gates ran on the full required set or a delta-scoped run. Do not open a second auditor for this step.
7. **Verdict.** PASS only when quality is PASS, blast radius is clean or residual-only, and the old exploit no longer reproduces. BLOCK -> `builder/60-repair` with all findings and the returned probe. INCONCLUSIVE or tool fault -> one fresh re-audit only if the fault code permits. REFUSED -> `90`. Tier is monotonic. **Routing** Repair loop: `builder/60` -> `30` -> `40` -> `50` -> auditor -> `15-delta`. Boundary: `50-release.md`. Hand off `task_id`, finding refs, probe ref, lane, head/tree, budget; no peer summaries.
**Policy refs** `policies/tiers.json`, `policies/checks.json`, `policies/risk-map.json`, `policies/severity.json`, `policies/dispatch-rules.json`, `policies/phases.json`, `policies/escalation.json`; `policies/schemas/finding.json`, `policies/schemas/auditor-verdict.json`, `policies/schemas/hacker-result.json`, `policies/schemas/repro-spec.json`; `agents/auditor.md`, `agents/hacker.md`.
**Done / failure codes** Done: `DISPATCH` with `reason_code: OK`; quality PASS routes to `50`. Failure: `HALT` with `BUILDER_BLOCKED`, `CYCLES_EXHAUSTED`, `BUDGET_EXCEEDED`, `RISK_RECORD_MISSING`, `SIG_INVALID`, `TREE_MISMATCH`.
