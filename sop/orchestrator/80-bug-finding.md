# 80 — Bug-finding sweep
**Mode:** `BUG_FINDING`
**Purpose** Hunt defects across one target with one auditor-led sweep and one hacker campaign: the auditor maps the AST over the whole target, ranks the inventory, dispatches exactly one whole-target campaign, verifies every claim itself, de-duplicates, assigns severity, and writes one bug report. **Topology** Orchestrator -> one auditor sweep -> one hacker campaign -> one report. The auditor is the campaign parent only in `BUG_FINDING`; the release-engineer is the campaign parent for the release train at GATE. The orchestrator never dispatches a hacker; builders never receive hacker output. No other edge exists.
**Inputs** Target paths, base/head; tier/variant from `policies/risk-map.json`; `policies/attack-catalog.json` (items, `#/campaign`), `policies/phases.json`, `policies/checks.json`, `policies/schema-fuzz.json`, `policies/severity.json`, `policies/tiers.json`, `policies/reuse.json`; `policies/schemas/bug-report.json`.
**Memory** Read `basemind_memory` (`list`/`search` filtered by `role:orchestrator`) at orientation; put one record at task end and whenever a seam, gotcha, or decision is found. Memory is advice, never evidence; re-run a remembered finding before citing it (`sop/00-memory.md`).
**Procedure**
1. **Scope and budget (orchestrator).** Record target paths, base/head, the whole-target scope, applicable catalog classes, and the sweep budget. Do not pre-cut the target into batches. Mixed scope raises tier; it never falls.
2. **Dispatch one sweep.** Mint one auditor task context at the target head/tree and dispatch one auditor session with the target, budget, catalog classes, and closure ref. Do not ask for interim batch reports and do not open a second auditor per flow or per batch.
3. **AST inventory (auditor).** Use `basemind_code` modes `symbols`, `outline`, `references`, `callers` and `basemind_graph` mode `calls` to enumerate entry points (URLs, views, serializers, tasks, webhooks), sources (request/headers/files/tenant), sinks (ORM/SQL, templates, HTTP, money state, session), guards, and data-flow edges. Record `flow_id | source | sink | path | guard | tier`.
4. **Rank and prune (auditor).** Money, auth, tenant, deserialization, and state transitions first; drop unreachable flows and mark guessed edges unknown, not safe. Keep the inventory whole: the interaction between surfaces is the point. Do not cut it into batches and do not dispatch per-subsystem children. One K1 run may serve the sweep within `policies/concurrency.json`.
5. **One campaign.** Dispatch exactly one hacker campaign for the whole target with `sop/auditor/30-hacker-relay.md`: one bounded prompt, one schema-valid result covering every catalog item it touched, with per-item attempts and evidence. No drip-fed item list and no second campaign on the same target.
6. **Verify every claim (auditor).** Re-run each claimed finding with `factory repro`; admit only reproduced results. Assign severity from `policies/severity.json` by class and tier_of(locus), never from a proposer. Normalize class + locus + symbol, merge duplicates, keep the strongest repro, and record each merge.
7. **Report once.** Write `policies/schemas/bug-report.json`: report id, campaign id, task context id, tree, auditor session, flows total/tested/not-run, findings with fingerprint and verification, duplicates merged, coverage note, and verdict (`COMPLETE|PARTIAL|BLOCKED`). `PARTIAL` and `BLOCKED` name what was not run.
8. **Route once.** Confirmed defect -> `20-bugfix.md`, clustered by class and locus. Spec/design cause -> `40` or `30`; architecture -> `auditor`; policy/risk gap -> `90`. Findings route back once, in the report; no per-batch round trips.
9. **Stop at budget.** Remaining flows are `NOT_RUN`; never present an unexamined surface as clean or upgrade `PARTIAL` to `COMPLETE`. **Routing** The single report returns to the orchestrator. Repair -> `20`; design -> `30`/`40`; risk -> `90`. Hand off report id, campaign id, findings, coverage, and verdict.
**Policy refs** `policies/attack-catalog.json`, `policies/phases.json`, `policies/checks.json`, `policies/schema-fuzz.json`, `policies/risk-map.json`, `policies/severity.json`, `policies/tiers.json`, `policies/reuse.json`, `policies/concurrency.json`; `policies/schemas/finding.json`, `policies/schemas/hacker-result.json`, `policies/schemas/bug-report.json`; `agents/hacker.md`.
**Done / failure codes** Done: `RECORD` with `reason_code: OK`, one bug report, coverage, routed findings. Failure: `HALT` with `BUDGET_EXCEEDED`, `CYCLES_EXHAUSTED`, `RISK_RECORD_MISSING`, `SIG_INVALID`.
