# 80 — Bug-finding sweep
**Mode:** `BUG_FINDING`
**Purpose** Hunt defects across a target with one auditor-led sweep: the auditor maps the AST, batches flows, dispatches multiple hacker children, verifies every claim itself, de-duplicates, assigns severity, and writes one bug report. The orchestrator dispatches one sweep, not a batch of audits. **Topology** Orchestrator -> one auditor sweep. That auditor may spawn multiple hacker children, one per bounded batch; each batch returns to the auditor. Batches never return to the orchestrator one by one. Findings return once, in the bug report. The orchestrator never dispatches a hacker; builders never receive hacker output. No other edge exists.
**Inputs** Target paths, base/head; tier/variant from `policies/risk-map.json`; `policies/attack-catalog.json`, `policies/checks.json`, `policies/schema-fuzz.json`, `policies/severity.json`, `policies/tiers.json`, `policies/reuse.json`; `policies/schemas/bug-report.json`.
**Procedure**
1. **Scope and budget (orchestrator).** Record target paths, base/head, maximum flows or batches, applicable catalog classes, and the sweep budget. Mixed scope raises tier; it never falls.
2. **Dispatch one sweep.** Mint one auditor task context at the target head/tree and dispatch one auditor session with the target, budget, catalog classes, and closure ref. Do not pre-cut batches, do not ask for interim batch reports, and do not open a second auditor per batch.
3. **AST inventory (auditor).** Use `basemind_code` modes `symbols`, `outline`, `references`, `callers` and `basemind_graph` mode `calls` to enumerate entry points (URLs, views, serializers, tasks, webhooks), sources (request/headers/files/tenant), sinks (ORM/SQL, templates, HTTP, money state, session), guards, and data-flow edges. Record `flow_id | source | sink | path | guard | tier`.
4. **Rank, prune, batch (auditor).** Money, auth, tenant, deserialization, and state transitions first; drop unreachable flows and mark guessed edges unknown, not safe. Cut the inventory into small batches: one subsystem or 5-10 flows. One hacker child per batch, each with a bounded prompt; children return only to the auditor. A single K1 run may serve the sweep within `policies/concurrency.json`.
5. **Verify every claim (auditor).** Re-run each claimed finding with `factory repro`; admit only reproduced results. Assign severity from `policies/severity.json` by class and tier_of(locus), never from a proposer. Normalize class + locus + symbol, merge duplicates, keep the strongest repro, and record each merge.
6. **Report once.** Write `policies/schemas/bug-report.json`: report id, batch ids, task context id, tree, auditor session, flows total/tested/not-run, findings with fingerprint and verification, duplicates merged, coverage note, and verdict (`COMPLETE|PARTIAL|BLOCKED`). `PARTIAL` and `BLOCKED` name what was not run.
7. **Route once.** Confirmed defect -> `20-bugfix.md`, clustered by class and locus. Spec/design cause -> `40` or `30`; architecture -> `auditor`; policy/risk gap -> `90`. Findings route back once, in the report; no per-batch round trips.
8. **Stop at budget.** Remaining flows are `NOT_RUN`; never present an unexamined surface as clean or upgrade `PARTIAL` to `COMPLETE`. **Routing** The single report returns to the orchestrator. Repair -> `20`; design -> `30`/`40`; risk -> `90`. Hand off report id, task context id, findings, coverage, and verdict.
**Policy refs** `policies/attack-catalog.json`, `policies/checks.json`, `policies/schema-fuzz.json`, `policies/risk-map.json`, `policies/severity.json`, `policies/tiers.json`, `policies/reuse.json`, `policies/concurrency.json`; `policies/schemas/finding.json`, `policies/schemas/hacker-result.json`, `policies/schemas/bug-report.json`; `agents/hacker.md`.
**Done / failure codes** Done: `RECORD` with `reason_code: OK`, one bug report, coverage, routed findings. Failure: `HALT` with `BUDGET_EXCEEDED`, `CYCLES_EXHAUSTED`, `RISK_RECORD_MISSING`, `SIG_INVALID`.
