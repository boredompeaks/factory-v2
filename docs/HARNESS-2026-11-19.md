# Harness defects — 2026-11-19

Fixes for `HARNESS-20261119-FACTORY.md`. Each section names the measured
symptom and the behaviour that replaces it.

## 1. BOOTTEST alerting env

`factory/checks/tests.py::_boot_env` now supplies inert values for
`SENTRY_DSN` and `ALERT_RECIPIENTS` in the canonical production env. They are
not added to `BOOT_REQUIRED_ENV_KEYS`: a correct fail-loud guard must boot, and
a missing alerting key must still be a boot assertion, not a SKIP.

## 2. Dispatch globs

Both layers changed:

- `policies/dispatch-rules.json` uses file-level forms
  (`backend/**/webhooks*.py`, `backend/**/views*.py`, `backend/**/views/*.py`)
  and `DR-MONEY-01` covers `backend/**/orders/**`.
- `factory/scope.py::dispatch_matches` also tries the product-root alias and
  samples wildcard scopes; a trailing `/**` matches the module file of the same
  name (`webhooks.py`, `views.py`). Dispatch is deliberately generous; `SCOPE`
  containment stays strict.

Recorded mints: `backend/orders/webhooks.py`, `backend/orders/views.py`, and
`backend/orders/views/checkout.py` all fire `DR-SECURITY-01` + `DR-MONEY-01`
(for SECURITY). `backend/cart/models.py` fires neither.

## 3. `tests_*.py`

`is_test_path` treats `tests_*.py` exactly like `test_*.py` in
`factory/checks/__init__.py`, `tools/smell.py`, and `tools/guard_delta.py` (the
last already did). `TEST_SET` and `BASE_FAIL_HEAD_PASS` now see the test files
Django projects actually use.

## 4. CONVENTION ruff cache

`check_convention` runs ruff with `RUFF_CACHE_DIR` in a temporary directory
outside the tree. A read-only runner can no longer turn a clean lint into
`ruff output was not valid JSON` (exit 2).

## 5. SEMGREP baseline

`check_semgrep` keeps the whole-file scan as raw evidence and makes the verdict
baseline-relative:

1. `--baseline-commit <base>` when the base commit is present and the worktree
   is clean enough for semgrep;
2. otherwise, findings whose span intersects an added line.

The proof detail records `N raw finding(s), M new (baseline=…)`. An unchanged
file no longer fails on its inherited findings.

## 6. SCHEMA_FUZZ spec env

`factory/proof.py::_call_runner` forwards only the documented schema keys from
the caller's environment: `FACTORY_OPENAPI_SPEC`, `OPENAPI_SPEC`,
`schema_path`, `FACTORY_SCHEMA_BASE_URL`, `SCHEMA_BASE_URL`, `base_url`, and
`FACTORY_DAST_TARGET_URL`. Arbitrary environment is still not copied.

## 7. THREAD_RACE capacity

`docker/services/compose.yaml` raises the PostgreSQL data tmpfs from 128 MB to
512 MB for both `pg2a` and `pg2b`. The running containers keep their old size
until the next `scripts/services_down.sh` / `services_up.sh`; the repetition
counts are unchanged.

## 9. CHANGELOG re-mint lineage

`check_changelog` now takes the allowed row ids from `Task-Id: <id>` (or
`Task: <id>`) trailers in `<base>..<head>`. With no trailer it falls back to
`ctx.task_id`, so existing tasks are unchanged. A re-mint keeps the historical
id in the row and repeats it in the commit trailer; the proof records
`allowed_task_ids` and `task_id_source`. See `docs/CHANGELOG-LINEAGE.md`.

## 8. Hacker dispatch request

`bin/factory campaign request --envelope <json> --prompt <file> --variant
<high|max> --json` validates the envelope shape, the `hacker_variant`, the
`agents/hacker.md` model pin against `policies/models.json`, and the prompt
(non-empty, UTF-8, no NUL, size cap) before the caller spends a provider call.
It returns the exact `agent`/`model`/`prompt` fields. Both campaign SOPs call
it first; a non-zero exit is `REFUSED`, not an opaque `400`.
